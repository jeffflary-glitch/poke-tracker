# Pokémon tracker dashboards

Three home-screen web apps on GitHub Pages, one shared codebase. Jeff has no coding background: explain changes in plain words and push straight to main.

| App | Page | Sheet | Photos |
|---|---|---|---|
| Jeff's | `index.html` → /poke-tracker/ | "Pokemon tracker Jeff" | `sealed/photos.json` |
| Max's (Jeff's son) | `max/index.html` → /poke-tracker/max/ | "Pokemon tracker Max" | `max/photos/photos.json` |
| Gavin's (Jeff's cousin) | `gavin/index.html` → /poke-tracker/gavin/ | "Pokemon tracker Gavin" (Jeff's Drive, shared with Gavin) | `gavin/photos/photos.json` |

- **All styles are in `app.css` and all code in `app.js`.** A feature change goes there once and both apps get it. Each page only holds its header text and a `window.PKT` settings block (sheet name/ID, photos folder, `store` prefix, and for Max his own `api` link).
- **Data:** each app has its own Apps Script project and link: Jeff's runs `apps-script/Code.gs` (link is the default `API` in `app.js`), Max's runs `apps-script/Code-max.gs` (link in `api` in max/index.html), Gavin's runs `apps-script/Code-gavin.gs` (link in `api` in gavin/index.html). Each project also has `Scan.gs` and `Prices.gs`. The two files are identical apart from the sheet. `?data=1` returns the sheet as data with its `sheetId`; `app.js` refuses data from a different sheet. Changes to these files only take effect after Jeff pastes them into that Apps Script project and deploys a new version (Deploy → Manage deployments → pencil → New version).
- **Scan cards** (header button, code in the "scan cards" section of `app.js`): the app POSTs `{action, pass, …}` as plain text to the same Apps Script link. `apps-script/Scan.gs` sits in BOTH Apps Script projects next to Code.gs / Code-max.gs; `scanSheetId_()` in each fixes which sheet scans write to. Scan.gs checks the passcode (Script Property `SCAN_PASSCODE`), asks Claude (`claude-sonnet-5-5`, effort medium, JSON schema output; key in Script Property `ANTHROPIC_API_KEY`) to read the cards, confirms each card and gets its TCGplayer market price from TCGdex. Then `scanWebCheck_` sends whatever TCGdex couldn't settle (`scanNeedsWeb_`: sealed items, no price, not found, confidence below high, or set/name warnings) to `claude-haiku-5-5` with the web search tool, one request per item in parallel, and reads the JSON line at the end of each answer (structured outputs can't be used there because web search always adds citations). A high- or medium-confidence answer may correct the set/number/name (and then its price is used); any answer fills a missing price; only a high one clears the earlier warnings; a low one changes nothing else. Price warnings (`scanChecks_`) run after this. On Add it writes Collection A–K (+ Grading A–D for top loader cards) using the storage units' jobs (see Storage units). The API key never goes to the phone or GitHub; the phone keeps only the passcode (`<store>-pass`).
- **Remove** (button at the bottom of a card's details, code in the "remove" section of `app.js`): action `remove` in Scan.gs (`scanRemove_`, same passcode, batch id so a retry can't remove twice) finds the Collection row by name, set, card # and location as displayed, lowers its Qty or deletes it by moving the A–K and Q values below up one (formula columns L–P never move, so their ranges stay intact), and deletes a top loader card's Grading row (input columns only). The app asks why (`RM_REASONS` in app.js = `SCAN_REASONS` in Scan.gs: Opened (sealed only), Sold, Traded, Gave away, Added by mistake); every reason but "Added by mistake" appends a row to the **Sold & Opened** tab (A–K inputs: Date, Name, Set, Card #, Category, Qty, Reason, Value Each from the sheet's price, Sold For Each, Was In, Notes; L–M totals are ARRAYFORMULAs in row 1). After Opened, the app offers "Scan what you pulled". **Pockets and top loader numbers are reused:** Scan.gs (`scanUsage_` / `scanFree_`) and the Storage tab's "Next open spot" formulas both pick the lowest number not in use in that unit, so a removed card's gap is filled first.
- **Bulk counts** (Scan → "Add bulk counts", action `bulk`, no AI): adds to or replaces the Qty of per-set count rows named like the existing ones — `<Set> non-foil bulk (count)` (Bulk Row 2 – Set), `<Set> reverse holo bulk (count)` / `<Set> holo rare bulk (count)` (Bulk Row 1 Back – Set), plus one shared `Trainer bulk (count)` and `Basic Energy (count)` (Bulk Row 3). Scanned cheap commons/uncommons default to "add to the bulk count" instead of their own row. Types live in `SCAN_BULK` (Scan.gs) and `BULK` (app.js); keep them in sync. Phone caching: bump the `?v=` tag on app.js/app.css in all three index pages when shipping app changes.
- **Loading creatures** (made from Jeff's own Gemini video; files in `fx/`, markup in the "loading creatures" section of `app.js`, moves in app.css). Refresh bubble (`#loadfx`): `fx/phoenix-fly.webp` is a 22-frame wingbeat sprite sheet (video frames 198–209 cut out, tracked on the chest, played forward then back) stepped with `steps(22,jump-none)` (the count must equal the frame count); the bubble flips the phoenix, casts a fireball that writes "Refreshing" in fire, lets it burn to ash and repeats (3.6s loop; letters delayed by `--i`, keep `backwards` fill so the word starts blank). Shown for opening the app, Refresh and coming back to it, not the 5-minute background refresh (`loadAll(true)`). Scan screen while reading: `fx/wolf-run.webp`, an animated 16-frame gallop (frames 166–181 of Jeff's gray-background video, cut out with the gray un-mixed from the edges) over looping ground streaks, `fx/wolf-run-still.webp` with Reduce Motion. While adding: `fx/wolf-charge.mp4` (video frames 0–59 then reversed: the wolf charges, bursts, draws it back in; muted, inline, looping, no autoplay with Reduce Motion, poster `fx/wolf-charge.jpg`). `FX` resolves `fx/` from app.js's own URL so both apps share the files; CSS URLs resolve from app.css.
- **Storage units** (Storage tab rows 2–30, edited in the app's Storage tab, action `units` → `scanSaveUnits_`): A Label · B Type (Binder / Top loaders / Bulk box / Sealed) · C Pockets per page · D Pages · E Capacity · F Job: set · G Job: min $ · H Job: max $; I In use · J Open · K Next open spot are per-row formulas (sources in `sheet/formulas.json`). A location is the unit's label plus its spot: `<label> P2 S5`, `<label> #7`, `<label> Row 2 – <set>`, `<label>`; a location's unit is the longest label it starts with (`scanUnitOf_`, `unitOf` in app.js, Collection S formula). Default labels "Binder", "Buffer", "Bulk", "Sealed Shelf" keep the old location texts valid. A new card goes to the unit whose job fits best (set job +100, each price limit +10, higher row wins ties; `scanMatches_`), skipping full ones. Renames rewrite locations; a unit holding cards can't be taken off, shrunk below its contents, or change type/pockets. Keep `scanFits_` (Scan.gs), `fitsJob` (app.js) and the Collection M/O formulas in step.
- **Collection M–P and S are array formulas in row 1** (`={"Header";MAP(…)}`), never per-row: M recommended unit, N required protection, O status ("Stored ✓", "Stored ✓ (your choice)", "⚠ Move to <label>", "⚠ No storage fits", "⚠ Unknown spot", "⚠ Needs price/location"), P protection check, S the row's unit. A card is fine where it is if that unit's job fits it, even if another fits better. R "Keep Here" (checkbox) marks a spot as the user's choice. Nothing may be written in M2:P or S2:S.
- **Move** (card details, action `move` → `scanMove_`): to another unit (next open pocket/number, a chosen page+pocket or #, or a bulk row), or `to:null` to set/clear Keep Here. Moving into a top loader adds a Grading row; protection (K) follows the new spot unless it's a graded slab.
- **Prices** (`apps-script/Prices.gs`, in every Apps Script project, set up by running `setupPriceChecks` once): `dailyPriceCheck` 6am, TCGdex prices for singles → H, Price History, Grading Raw NM (free). `weeklyPriceCheck` Sunday 8am: sealed by Haiku web search (`scanWebCheck_`), Grading PSA 10/9/8 by web search (`scanWebAsk_`, `PRICE_PSA_SYSTEM`), both only with `ANTHROPIC_API_KEY`; a Price & Value Logs row; email to Script Property `REPORT_EMAIL` (comma-separated) with the week's Price History changes, cards to move and unpriced items. These replace the Claude scheduled price tasks.
- **Type a card** (every app, Scan → "Type a card", action `lookup`, no AI): card number + foil, with optional name and set → `scanLookup_`. With no name, `scanCardsAtNumber_` finds the card at that number in every set with that printed total (narrowed to the typed set if one is close); one hit is used, several come back as `{choices}` and the app's "choose" step lets you tap yours (sent back with its name and set). With a name, `scanEnrich_` with `fromDb` runs the usual TCGdex check and takes name, rarity and type from the database; a misspelled name falls back to `scanFindByNumber_` (closest name among the cards at that number, `scanSimilar_` at least 0.5). The card joins the review list; Add is the normal `add`. A card with no non-foil printing is priced as its holo even if "No foil" was picked or read. On the review list, "Other versions" are buttons (`useVersion` in app.js) that switch the card to that printing's price and finish.
- **Saved data on the phone** is namespaced by `store` (`pkt-…` for Jeff, `pkt-max-…` for Max, `pkt-gavin-…` for Gavin) because the apps share one web origin. TCGdex picture caches (`pkt-tcg-…`) are shared on purpose.
- **Own photos:** add the image to the app's photos folder and list it in that folder's `photos.json`: sealed items by exact name, single cards as "Name Number" (e.g. "Tyrunt 070").
- **Sheet layout** (all sheets identical): Collection, Storage, Grading, Price & Value Logs, Price History, Sold & Opened, Settings. Collection Q is **Paid Each ($)**, an input (blank = unknown); the card details show Paid each, Paid total and Gain (Total Value − paid × Qty) when it's filled, and Remove moves Q and R with A–K.
