# Pokémon tracker dashboards

Two home-screen web apps on GitHub Pages, one shared codebase. Jeff has no coding background: explain changes in plain words and push straight to main.

| App | Page | Sheet | Photos |
|---|---|---|---|
| Jeff's | `index.html` → /poke-tracker/ | "Pokemon tracker Jeff" | `sealed/photos.json` |
| Max's (Jeff's son) | `max/index.html` → /poke-tracker/max/ | "Pokemon tracker Max" | `max/photos/photos.json` |

- **All styles are in `app.css` and all code in `app.js`.** A feature change goes there once and both apps get it. Each page only holds its header text and a `window.PKT` settings block (sheet name/ID, photos folder, `store` prefix, and for Max his own `api` link).
- **Data:** each app has its own Apps Script project and link: Jeff's runs `apps-script/Code.gs` (link is the default `API` in `app.js`), Max's runs `apps-script/Code-max.gs` (link in `api` in max/index.html). The two files are identical apart from the sheet. `?data=1` returns the sheet as data with its `sheetId`; `app.js` refuses data from a different sheet. Changes to these files only take effect after Jeff pastes them into that Apps Script project and deploys a new version (Deploy → Manage deployments → pencil → New version).
- **Scan cards** (header button, code in the "scan cards" section of `app.js`): the app POSTs `{action, pass, …}` as plain text to the same Apps Script link. `apps-script/Scan.gs` sits in BOTH Apps Script projects next to Code.gs / Code-max.gs; `scanSheetId_()` in each fixes which sheet scans write to. Scan.gs checks the passcode (Script Property `SCAN_PASSCODE`), asks Claude (`claude-sonnet-5-5`, effort medium, JSON schema output; key in Script Property `ANTHROPIC_API_KEY`) to read the cards, confirms each card and gets its TCGplayer market price from TCGdex (sealed items aren't in TCGdex: `scanSealedPrices_` asks `claude-haiku-5-5` with the web search tool for each one in parallel and reads the JSON line at the end of its answer; structured outputs can't be used there because web search always adds citations), and on Add writes Collection A–K (+ Grading A–D for $20+) using the routing rules from the pokemon-tracker skill and the Storage tab's next binder slot / buffer #. The API key never goes to the phone or GitHub; the phone keeps only the passcode (`<store>-pass`).
- **Bulk counts** (Scan → "Add bulk counts", action `bulk`, no AI): adds to or replaces the Qty of per-set count rows named like the existing ones — `<Set> non-foil bulk (count)` (Bulk Row 2 – Set), `<Set> reverse holo bulk (count)` / `<Set> holo rare bulk (count)` (Bulk Row 1 Back – Set), plus one shared `Trainer bulk (count)` and `Basic Energy (count)` (Bulk Row 3). Scanned cheap commons/uncommons default to "add to the bulk count" instead of their own row. Types live in `SCAN_BULK` (Scan.gs) and `BULK` (app.js); keep them in sync. Phone caching: bump the `?v=` tag on app.js/app.css in both index pages when shipping app changes.
- **Saved data on the phone** is namespaced by `store` (`pkt-…` for Jeff, `pkt-max-…` for Max) because both apps share one web origin. TCGdex picture caches (`pkt-tcg-…`) are shared on purpose.
- **Own photos:** add the image to the app's photos folder and list it in that folder's `photos.json`: sealed items by exact name, single cards as "Name Number" (e.g. "Tyrunt 070").
- **Sheet layout** (both sheets identical): Collection, Storage, Grading, Price & Value Logs, Price History, Settings. Each sheet has its own Sunday price check (scheduled task) that writes prices and appends Price History rows.
- Test changes headlessly against both pages before pushing (Playwright is available; mock `script.google.com` with sample data).
